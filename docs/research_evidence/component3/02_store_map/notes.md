# Store map evidence notes

- **Objective:** Design, implement, visualize, and validate a connected store-navigation graph and AprilTag checkpoint layout for the Component 3 prototype.
- **Problem being solved:** The repository contained empty map and checkpoint placeholders. Component 3 requires a reproducible simulated environment in which later routing and localization work can reference stable nodes, metric coordinates, store sections, and checkpoints.
- **Methodology:** Model the walkable floor as a connected, undirected, weighted graph in a declared metric coordinate system. Use six vertical section spines connected by south, middle, and north cross-corridors. Place checkpoints at the entrance, checkout, and every south aisle access. Generate figures directly from the JSON and validate references and invariants automatically.
- **Implementation details:** The simulated footprint is 24 m east-west by 18 m north-south. The origin is the south-west corner; +x points east and +y points north. The graph contains 20 nodes and 29 undirected edges. Every edge weight is a positive walking distance in metres and is at least the straight-line distance between its endpoint coordinates. The visualization script composes SVG from JSON with the Python standard library and converts it to 1700×1120 PNG through an installed macOS renderer.
- **Tools and libraries:** Python 3.14.0 standard library (`argparse`, `csv`, `json`, `math`, `pathlib`, `subprocess`, and related modules); macOS Quick Look renderer; `sips-316` for PNG inspection; Git commit `0b4340f28acd805b9b4821e07a47341e06ee7133`. No new package was installed.
- **Inputs and outputs:** Inputs are `data/store_map/store_graph.json`, `data/store_map/apriltag_layout.json`, `shared/db/seed/products.csv`, and `shared/db/seed/store_locations.csv`. Outputs are the two registered PNG figures and `evaluation/comp3/test_results/store_map_validation.txt`.
- **Algorithms or models used:** Graph construction, undirected breadth-first connectivity validation, uniqueness checks, reference checks, and coordinate-distance consistency checks. Dijkstra and Held-Karp were not implemented. No navigation model, CNN, or live camera detector was trained or implemented.
- **Test procedure:** Run `python3 data/store_map/validate_store_map.py --output evaluation/comp3/test_results/store_map_validation.txt`; run `python3 data/store_map/visualize_store_map.py`; inspect the generated PNGs; register the existing artifacts with `register_evidence.py`; then run `python3 docs/research_evidence/component3/tools/validate_evidence.py`.
- **Observed results:** At 2026-10-13 22:59:17 +05:30, all 15 map checks passed: JSON structure, unique node IDs, valid edge references, positive distances, undirected edge uniqueness, graph connectivity, entrance/checkout presence, coordinate system and bounds, edge geometry, six section references, product references, unique tag IDs, tag-node mappings, tag physical properties, and tag-coordinate consistency. All 20 nodes were reachable. The graph has 29 edges, six sections, and eight checkpoints. Both 1700×1120 PNGs were generated and visually inspected. The evidence validator reported `Component 3 evidence structure is valid; 3 indexed artifact(s).`.
- **Product-location mapping:** Both seed CSVs contained header rows only. Therefore there were zero actual product IDs, zero store-location rows, zero confident product mappings, and no individual products to report as unmapped. No product IDs or seed records were invented or altered. Mapping must be revisited when authorized seed rows exist.
- **AprilTag placement strategy:** Family `tag36h11`; simulated marker size 0.16 m. IDs 100 and 101 map to entrance `ENT` and checkout `CHK`. IDs 110–115 map to south access nodes `B1`–`B6` for Produce, Bakery, Dairy, Meat, Frozen, and General Grocery. Orientations are simulated degrees counter-clockwise from +x and require later camera field validation.
- **Problems encountered:** Matplotlib and other Python imaging packages were not installed. The first installed renderer attempted, `sips`, returned `Cannot extract image from file` for generated SVG. The sandboxed Quick Look attempt then failed with a sandbox-extension error.
- **Solutions attempted:** Kept the visualization dependency-free, added a renderer fallback, and reran the script with approved access to the installed macOS Quick Look renderer. The corrected figures were regenerated after visual inspection identified transparency and label-placement issues.
- **Limitations:** Dimensions, edge weights, tag size, positions, and orientations are simulated prototype design values, not field measurements. Shelf footprints, obstacles, one-way constraints, accessibility clearances, dynamic congestion, camera visibility, print quality, and tag detection range have not been evaluated. The current visualization conversion depends on macOS Quick Look when `sips` cannot decode SVG. Product mapping remains unavailable because the seed data is empty.
